# 生图流程详述

本文件记录这套横版设定图的完整制作流程、每一步的目的、以及实际踩到的坑。
所有脚本在 [`scripts/`](../scripts/README.md)。

---

## 0. 环境

| 项 | 要求 |
|---|---|
| Python | 3.11+（实际使用 3.13） |
| 依赖 | `Pillow`（唯一第三方依赖） |
| 绘图 | 本机 OpenAI 兼容接口 `http://127.0.0.1:8317/v1`，通过 `gpt-image-gen` 技能的 `src/gen.py` 调用 |
| 模型 | `gpt-image-2.5-sunburst`（也提供 `-flare` 与无后缀版本） |
| 字体 | Windows 微软雅黑 `msyh.ttc` / `msyhbd.ttc`（生成设定板文字用） |

路径不要写死：复制 `scripts/workflow_config.example.json` 为 `scripts/workflow_config.json`
并按自己的机器修改，或设置环境变量 `AICHAN_LIB_ROOT` / `AICHAN_IMAGE_GEN`。
`workflow_config.json` 已被 `.gitignore` 忽略。

## 1. 逐张辨认原图，定清单（**最容易出错的一步**）

**先看图，再写清单。不要套模板。**

对每个角色要确定：

1. **身份锚点** —— 发色与渐变、瞳色（有异色瞳的要写清左右！）、标志性配件、体型。
2. **配色** —— 逐角色不同。智谱 GLM 娘全身只有黑 / 白 / 银 / 蓝、**没有金色**；
   Kimi 娘则是深藏青 / 白 / 银 / 淡紫 + 金 + **彩虹**。照搬别的角色的配色描述会直接毁掉成品。
3. **服装层次** —— 从上到下的层次顺序、前短后长之类的不对称剪裁。
4. **哪些配件真的存在** —— 逐件核对，**不要凭印象写**。
5. **哪些属于被遮挡** —— 手挡住的道具、被头发遮住的颈饰等。

> **实际教训**：智谱 GLM 娘最初凭印象写了「过膝靴 / 手套 / 耳坠」，
> 写提示词时核对才发现立绘上是白色系带高跟短靴、双手赤裸、无穿孔耳环。
> 最终按真实存在的部件交付。**清单错了会让 22 张图里有 3 张白跑，而且会污染设定。**

产物：`制作清单.json`（22 条任务）+ `角色视觉设定.md`（含"补全设计范围"一节）。

## 2. 写提示词

每条提示词的结构固定为三段：

```
[共用身份段]  角色身份唯一来自所给原始立绘。逐项描述身份锚点、配色、服装、配件、画风约束…
    +
[共用约束段]  沿用原图日系二次元画风；纯白无纹理背景；不加文字/标尺/水印；
              不生成拼贴、网格、多个视图或小插图；每张图只绘制本任务指定的一个对象或视图。
    +
[本张专属段]  本次只绘制 XXX。必须还原：…（逐项列出）… 不要画 YYY。
```

要点：

- **把"不要画什么"写清楚。** 三视图要写"不拿道具、不要原图那个 pose"，
  表情图要写"不要画手、不要画全身"。
- **异色瞳要逐张重复写左右。** 换表情时模型最容易把两只眼睛画成同色。
- **易错形状要写反例。** Kimi 娘的月牙要写"不是满月或星星"、三棱镜要写"不是宝石或水滴"；
  Gemini 娘的四角星要写"**绝不可画成五角星**"；智谱娘的徽记要写"不要改成星形或字母"。
- **文字标识要写"必须是拉丁字母 K"。**

尺寸与质量：

| 用途 | 尺寸 | 质量 |
|---|---|---|
| 三视图（竖长） | `1536x2560` | `high` |
| 表情（胸像方形） | `1536x1536` | `high` |
| 服装单品 | `1536x1536` | `high` |
| 道具饰品 | `1536x1536` | `high`，细小徽记 / 文字标识用 `xhigh` |

> 实测：请求尺寸与实际返回尺寸不同（请求 `1536x2560` 实际返回约 `941x1672`）。
> 拼接时以 Pillow 读到的**实际尺寸**为准，不要把请求尺寸当成实际尺寸写进记录。

## 3. 逐条生成

```powershell
# 单条（任务未完成时才执行；已完成会拒绝重跑）
python scripts/render_asset.py A01_三视图_正面

# 批量：串行 + 失败自动退避重跑（推荐）
.\scripts\run_retry.ps1 -Log .\00_生成记录\_worker日志\workerR.log -MaxAttempts 5 -BaseSleep 30
```

`render_asset.py` 做四件事：读提示词 → 调本机接口（参考图走 `images/edits`）→
把 PNG 落到对应分类目录 → 写 `生成记录/<id>.json`（含模型、质量、尺寸、耗时、输出 sha256）。

**并发上限很重要：**

| 并发数 | 结果 |
|---|---|
| 1（串行） | 稳定，偶发失败可退避重跑 |
| 2 | 多数时候可以 |
| 3–4 | 触发上游缓冲超限：`507 exceeded request buffer limit` / `503 auth_unavailable` / `500 unexpected EOF` |

失败的记录会保留，`run_retry.ps1` 下一轮会自动挑出未成功的任务重跑，
并做指数退避（`BaseSleep × 尝试次数`）。**不要为了赶时间降质量或换模型。**

## 4. 逐张目检

**每张都要开图看**，重点：

- 身份是否走形（发色 / 瞳色 / 鳍耳 / 狐尾 / 徽记这类标志物）
- **左右是否镜像**（异色瞳、单侧腿环、单侧发饰最容易错）
- 服装层次与配色是否与立绘一致
- 徽记与文字标识形状 / 拼写是否正确
- 背景是否纯白、有没有多余的场景元素、文字、水印

不合格的**另存 v02 版本重生成**，v01 记录保留在 `生成记录/历史记录/`。

> **审图的坑**：这些素材是 RGBA，**alpha 是柔性遮罩**——几乎找不到"完全不透明"的像素，
> 全透明区约占 25–30%，alpha 有 256 个取值。
> 所以审图时**必须先合成白底再转 RGB**：
> ```python
> im = Image.open(p).convert("RGBA")
> bg = Image.new("RGBA", im.size, "white"); bg.alpha_composite(im)
> rgb = bg.convert("RGB")      # ← 正确
> # im.convert("RGB")          # ← 错误：透明区会变成黑底并出现噪点
> ```
> 我一开始就是直接 `convert('RGB')` 做了张接触印样，看到黑底和蓝色噪点，
> 一度以为素材坏了，排查后确认是**预览代码的错**，素材本身没问题。

## 5. 拼接横版设定板

```powershell
python scripts/compose_landscape.py
```

布局规则（与常见竖版设定板的关键区别）：

- 画布为**横版**：`board_w > board_h`，脚本内置断言，不满足直接报错。
- **每个分区占一行**，行内素材从左到右排开，不换行；
  行内各素材在自己的格子里居中对齐。
- 格子宽度 = 该分区最宽素材 + 内边距；行高 = 该分区最高素材 + 标签区 + 说明区。
- 分区标题 + 行内说明在左上，右侧标注画布尺寸与宽高比。
- 所有文字用 `fit_font()` **自适应字号**——长标题会自动缩小，不会溢出格子压住素材。
  （这是修过的缺陷：最初直接用生成记录里的长描述当标题，GLM 那边的标题长到把小图压在下面。）

**像素保真**（样本的核心要求，也是本流程的硬约束）：

- 素材**原生像素 1:1 粘贴**，`scale` 恒为 `1.0`，不缩放、不裁切；
- 透明像素按标准 alpha 合成白底后再粘贴；
- 粘贴后**立刻原地裁剪回来逐字节自检**，不一致就断言失败。

产物：`*_原像素.png`、`*_浏览预览.jpg`（长边 4200）、`拼接布局与素材索引.json`。

## 6. 独立核验

```powershell
python scripts/verify_board.py --all
```

**不采信拼接脚本的自述**，从磁盘重新算：

1. 母版实际尺寸与宽高比（是否真横版、是否落在 1.3–2.4）；
2. 每条 placement：重新打开素材、合成白底、与板上矩形**逐字节**比对；
3. placement 的 `width/height` 是否等于素材原始尺寸、`scale` 是否为 1.0；
4. 格子 / 素材两两是否重叠、是否越出画布；
5. 素材 sha256 是否与记录一致、是否有重复。

五个角色的结果：全部 `pass`，逐字节 **22/22**，零重叠、零越界、零缩放、零重复。

## 7. 生成便于查看的小尺寸图

```powershell
python scripts/make_viewable.py --all
```

母版是 1.2–1.6 亿像素、约 30MB 的 PNG。**Windows 照片查看器会解码失败，
并统一误报「文件不存在，可能已被移动或删除」**——这句报错是误导，文件其实完好。
（已核实：PNG 签名正确、IHDR 声明与实际一致、Pillow 可完整解码。）

所以另外产出长边 ≤ 4000px 的 JPG：

- `*_全板总览_查看用.jpg` —— 整板缩览，看版式；
- `*_<分区>_查看用.jpg` —— **按该分区素材实际占据的范围裁切**后缩放，
  而不是整板宽度均分，这样每格都占满画面、清晰度足够审图。

## 8. 常见故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `507 exceeded request buffer limit` / `503 auth_unavailable` | 并发过高触发上游缓冲上限 | 降到单进程串行，退避重跑 |
| `500 unexpected EOF` | 上游间歇性断连 | 重跑即可，多数第二次就过 |
| `401 / 403` | 私有配置里的密钥问题 | 检查绘图工具配置；**不要**把密钥写进提示词或提交 |
| `404` | 模型 id 不对 | 用 `python src/gen.py --list-models` 核对 |
| 看图器报「文件不存在」 | 母版像素过大、查看器解码失败 | 用 `06_便于查看/` 里的 JPG |
| 拼接脚本报「未满足横版要求」 | 素材太少或太窄，拼出来是竖版 | 检查清单是否齐全；必要时调整每行格子数 |
| 接触印样出现黑底与噪点 | 对 RGBA 直接 `convert('RGB')` | 先合成白底再转 RGB |
