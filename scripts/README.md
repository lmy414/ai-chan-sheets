# 脚本

这里只有 5 个文件：1 个提示词模板，4 个拼板、切片与核验工具。

生图那一步不在这里。它依赖作者本机的绘图工具（gpt-image-gen 技能调 `gen.py`），
别人机器上没有，所以没随仓库发布。第 15 至 17 条改用内置 `image_gen` 工具。
第 18 条使用本机 API，模型为 `gpt-image-2.6-sunburst` 与 `gpt-image-2.6-flare`，质量均为 `high`。
两种方式都按下面的字段格式保存提示词和生成记录，再复用同一套拼板与核验脚本。

## 环境

- Python 3.11 或更高。
- Pillow，三个工具脚本的唯一第三方依赖。
- 中文字体。拼板脚本默认取 Windows 的微软雅黑 `msyh.ttc`，其他系统改脚本里的 `FONT_DIR` 即可。

```bash
pip install Pillow
```

## 文件一览

| 文件 | 作用 | 依赖 |
|---|---|---|
| `make_prompts.py` | 提示词模板。按角色改写后生成 `制作清单.json` 与 22 条 `提示词/*.json` | 只要 Python |
| `compose_landscape.py` | 拼横版设定板，原生像素 1:1 粘贴，带逐字节自检 | Pillow |
| `verify_board.py` | 独立核验成品板，从磁盘重算，不采信拼板脚本的自述 | Pillow |
| `make_viewable.py` | 出便于查看的小尺寸图 | Pillow |
| `make_native_slices.py` | 从母版裁四个分区的 1:1 原像素切片 | Pillow |

## 用法

四个工具脚本的参数都是**角色工程目录**，不是仓库根。拼板与核验脚本同时支持
工程目录中的 `00_生成记录/` 和仓库目录中的 `生成记录/`。第 13 至 18 条包含全部
独立素材，可以直接从仓库目录重建。旧条目需要先从本地工程补齐独立素材。

在仓库根目录执行。下面的第 13 条已包含独立素材，无需重新生图：

```bash
# 1. 以独立素材重建母版
python scripts/compose_landscape.py "设定图/13_GPT娘_Q版白紫龙娘"

# 2. 独立核验母版与 22 张素材
python scripts/verify_board.py "设定图/13_GPT娘_Q版白紫龙娘"

# 3. 生成查看图和 4 张原像素切片
python scripts/make_viewable.py "设定图/13_GPT娘_Q版白紫龙娘"
python scripts/make_native_slices.py "设定图/13_GPT娘_Q版白紫龙娘"
```

制作新角色时，可以修改 `scripts/make_prompts.py` 顶部的配置，生成清单与提示词，
再用自己的绘图工具生成素材并写入记录。生图步骤不包含在仓库脚本中。

`verify_board.py` 全部通过时退出码为 0，任一角色不通过为 1，可以直接接进 CI。
它可以一次接多个目录。

## 提示词文件的字段

`提示词/<任务id>.json` 每条一项，字段如下。

| 字段 | 说明 |
|---|---|
| `id` | 任务 id，也是文件名主干，例如 `A01_三视图_正面` |
| `group` | 所属分区目录名，例如 `01_三视图` |
| `model` / `quality` / `size` | 生成参数。内置工具记录为 `image_gen (built-in)`、`tool-managed` 和提示词要求的构图；实际像素尺寸见生成记录 |
| `refs` | 参考图数组。相对路径从仓库根算；`@任务id` 表示引用另一条任务的产出 |
| `prompt` | 提示词正文 |

工程目录使用 `00_生成记录/<任务id>.json`，仓库目录使用 `生成记录/<任务id>.json`。
拼板脚本读取这些记录来定位素材：

| 字段 | 说明 |
|---|---|
| `status` | 必须是 `success`，否则拼板时会报错停下 |
| `group` | 素材所在目录 |
| `output` | 素材文件路径 |
| `dimensions` | 素材实际像素尺寸，必须与文件一致 |
| `output_sha256` | 素材文件哈希，拼板前会校验，不一致就报错 |

内置工具不暴露底层模型、质量档位和用量，因此对应返回字段为 `null`，不推测这些参数。

`制作清单.json` 里的 `tasks` 是任务顺序，`sections` 定义分区的标题与顺序，
`native_name` 与 `preview_name` 是成品文件名。

## 两个硬约束

1. **像素保真。** `compose_landscape.py` 只做 1:1 粘贴，`scale` 恒为 1.0，不缩放不裁切。
   粘贴后原地裁剪回来逐字节自检，不一致直接断言失败。
2. **画布必须横版。** 要求 `board_w > board_h`，否则断言报错。
   这是本套流程与常见竖版设定板的关键区别。

## 生成素材时的三条实测经验

这三条与具体工具无关，换任何绘图工具都成立。

1. **先看图再写清单。** 不要套模板。智谱 GLM 娘最初凭印象写了「过膝靴 / 手套 / 耳坠」，
   核对立绘才发现三件都不存在，最终改成交付系带高跟短靴、袖饰与臂环、狐耳。
2. **串行比并发稳。** 作者本机实测：并发到 3 个或 4 个请求就会触发上游缓冲超限。
   失败的任务攒下来重跑，比提高并发划算。
3. **透明底素材审图前先合成白底。** 直接对 RGBA 调 `convert('RGB')`，
   透明区会显示成黑底并出现噪点，那是预览代码的问题，不是素材缺陷。

更多细节见 [`../docs/生图流程.md`](../docs/生图流程.md)。
